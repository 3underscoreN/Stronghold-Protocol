### 37.3 COST／SP 飘字（#657）

来源：[issue #657](https://github.com/sganggs/Stronghold-Protocol/issues/657) 正文截图及维护者对范围的回复。
已查看扣费截图 `91695d1f-5010-420f-8a67-838dfa366e7a`（红色 COST −3）及技力截图
`3e5a41e1-a46d-43f4-bd8b-447da3323d9f`（青色 SP 3）。白色正 COST、青色 SP、红色负 COST
位于干员上方。字号、色值、0.9 秒寿命、居中位置及小数最多两位是 [ASSUMED]，未逐像素或逐帧复刻。

按维护者指定的 [ASSUMED] 展示范围：官方数字模式保留情报官技能、冲锋手击杀回费与行商实际扣费；
非官方模式额外显示尖兵技能回费。德克萨斯开场费用、自然费用及忍冬天赋的自然回复增量不显示。
SP 仅 `bond`／`talent`／`skill` 额外回复（含迅捷、萨尔贡），排除自然、普攻、受击、初始技力、
退款及未列来源。两类都受「显示伤害数字」总开关控制，Pixi 与简化棋盘同一来源过滤。

没有把既有 `spGain` 请求或 `fx('sp'/'dp')` 估值作为数字：`gainSp` 在 hook、充能转换、上限之后
计算实际 SP 增量；`addDp` 可选来源参数记录实际 DP 变化，原返回值不变。零到账、阻回、技能期间
拒绝的回复不显示。费用来源的 kit 调用仅补上来源，不修改金额或时序，原特效仍保留且不重复出数字。
`resourceNumbers` 为仅显示用的 Battle 构造选项，默认关；浏览器主线程／Worker 和服务器直播的
战斗入口打开，预演／验证／golden 不打开，因此 golden 的既有事件计数和全部结果字节不变。
事件 `['resource', id, 'cost'|'sp', actualDelta, reason]` 属于可丢弃的短暂外观事件。
测试覆盖上限、充能跨格、hook 改写／拒绝、阻回、实时来源、两种数字模式及开关、Pixi 标签和回收。
红字判定与 #412 的字体／合并自定义不属于本项，保持不变。

### 37.4 部署缩放中间档（#692）

来源：[issue #692](https://github.com/sganggs/Stronghold-Protocol/issues/692) 的维护者回复：增加中间档，
棋盘适度放大，商店缩小而不完全收起。官方没有中间档；商店缩至 70%、镜头取官方展开／收起参数
中点为 [ASSUMED]，仍应用 HUD 避让，覆盖普通休整与最终攻势左右半场。
设置「部署时收起商店」改为关闭／适度缩小／完全收起；保存值沿用 false／true，中间档为 `partial`，
旧设置不迁移、默认仍完全收起。仅自己的休整棋盘拖起干员、装备或召唤物时启用，朝向选择期间保持；
释放、完成或取消后还原，拖拽中切换档位立即生效。手动已收起的商店继续收起；敌方情报的镜头及
延迟归还逻辑不变。浏览器覆盖触屏静止手指下的目标同步、精确镜头归还、商店缩放、朝向和中途关闭；
单元覆盖三档存储、普通／最终攻势左右镜头与手机 HUD。纯界面修改，默认 golden 无变化。

#### #892：敌波预览里隐藏的盟约圆盘拦截点击

报告者在 0.3.3（Chrome 155 / Windows）中把镜头切到敌波预览后，点击棋盘上排的预览敌人常弹出盟约详情：盟约栏和效果栏
只是 `opacity: 0` 加 `pointer-events: none`，没有 `visibility` 隐藏。本机 Chrome 153 / macOS 的命中测试与真实点击都
没有复现（handoff round54 ISSUES54）。修正采用范围最小、与浏览器无关的做法：`.gm.is-pen` 下两组 HUD 在淡出结束后
同时 `visibility: hidden`（`visibility 0s linear var(--t-med)`，淡出动画不变），离开预览时 visibility 立即恢复再淡入。
`visibility: hidden` 的元素不参与命中测试，不再依赖 `pointer-events` 在绝对定位渐隐层上的实现。新增
`test/ui/pen-hidden-hud.e2e.test.js`：静态检查规则，浏览器部分在 Pixi 与简化渲染下确认预览中点击圆盘位置不命中
HUD、不弹盟约详情，返回备战后圆盘可点开。没有玩法变化，回放基准不动。

### 37.6 人机让出队友的特化干员、少选鸭爵（#121，round54）

报告：「我玩潘格尼尼，AI 玩歌利亚大量抓我拉特兰」；AI 选鸭爵后自己守不住，金币怪还冲垮队友的防线。原规则（PR #407）只对
5–6 阶、且与存活队友**开局策略**盟约重叠的共享干员扣 18 分，低阶拉特兰不受影响；选策略时鸭爵也不会因为队友降低权重。

改动（`server/match/bot.js`，均为 [ASSUMED] 的人机取舍，不是官方规则）：

- `teammateBonds`：每名存活队友需要的盟约 = 开局策略的盟约 + 公开盟约栏上的主核心盟约（`mainCoreBond`），减去自己开局
  策略需要的盟约和本模式关闭的盟约。真人与人机一样；多名队友不叠加；淘汰的队友不再计入；单人为空。
- 买牌：干员的盟约落在其中时扣分，5–6 阶仍是 18，1–4 阶为 12。凑齐三合一（MERGE_HIT +30/+40）或缺阻挡／治疗
  （+10／+14）仍压过这项扣分。
- 选策略：机制会改变队友敌人的策略（鸭爵「神秘顾客」：第 5 回合起自己和队友遭遇的部分敌人换成鸭爵／高普尼克／流泪小子／
  圆仔）在有存活队友时只保留十分之一权重（`MATE_BURDEN` = 0.1，按描述识别）；单人照旧。

测量（`node tools/botbench.mjs --configs coop4:ABYSS,coop4:HARD,coop2:HARD --seeds 20 --seed 1 --jobs 3`，改前 dev
`f07b8965` / 改后）：四人终极胜 1/20 → 1/20（到达首领 8 → 7，漏怪 225.0 → 237.7）；四人绝境 12/20 → 13/20（剩余生命
43.5 → 50.1）；双人绝境 10/20 → 10/20（到达首领 13 → 17，剩余生命 16.9 → 25.9）。R10 盟约阶数之和 6.1 → 6.5（终极）、
6.1 → 6.3（四人绝境）：队伍的盟约更分散。全人机队伍的胜率在 20 局的噪声内不变；这项改动面向和真人组队时的体验。

回放基准：单人场景全部不变；双人／三人／四人的对局场景移动（默认 12 个，第一期下半 7 个、第一期上半 7 个、第二期上半
8 个），全部重新生成。首次后果是开局策略和采购的不同：例如默认 `coop2-NORMAL-1-unowned-roster` 第 0 回合人机抽到的
策略改变（`prepFunds` 0 → 4），`coop4-ABYSS-7` 由胜（第 14 回合）变为负（第 13 回合）、`coop2-HARD-4` 由第 12 回合
全灭变为第 13 回合失败。测试：`test/match/bot-smarter.test.js` 新增两项（低阶避让、自身策略豁免、主盟约、淘汰；
鸭爵有队友时的抽取率 < 单人的四分之一），原「5 阶以下不受影响」的断言改为逐卡检查 1–4 阶扣 12、5–6 阶扣 18。
